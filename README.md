# Автоматизация разбора файлов

[![hexlet-check](https://github.com/kicha3007-boop/ai-automation-project-439/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/kicha3007-boop/ai-automation-project-439/actions)

Консольная программа на JavaScript (Node.js), которая приводит в порядок общую папку компании.

- `files` разбирает папку: определяет тип каждого файла по расширению и первым байтам, отделяет
  документы от посторонних файлов и от тех, что требуют ручного разбора, находит дубликаты
  (по хешу содержимого и по приведённому имени) и собирает реестр `registry.csv`.
- `contacts` находит в папке выгрузки контактов (по колонкам, а не по именам файлов), приводит
  колонки к одной схеме, нормализует телефоны, почту и имена, склеивает повторы и собирает
  чистую таблицу `contacts.csv`.
- Обе команды пишут отчёт для человека `report.txt` и отчёт для программ `report.json`.

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-automation
Как это должно работать: https://files.hexlet.app/a/fjioad

## Всё работает локально

Программе не нужны ни сеть, ни внешние сервисы, ни нейросети, ни ключи API: она читает файлы
с диска и пишет результат на диск. Файла `.env` нет, потому что настраивать нечего. Тесты
собирают свою папку-хаос во временном каталоге и тоже ничего не скачивают.

## Установка

Нужны Node.js 22 или новее (Хекслет проверяет на Node.js 26), npm и make.

```bash
git clone https://github.com/kicha3007-boop/ai-automation-project-439.git
cd ai-automation-project-439
make setup     # npm ci: зависимости по package-lock.json
npm link       # необязательно: команда file-automation появится в системе
```

Без `npm link` программа запускается как `node bin/file-automation.js ...`.

## Данные компании

Набор файлов для работы лежит в отдельном репозитории и в этот не попадает (`company-files/`
в `.gitignore`):

```bash
git clone --depth 1 https://github.com/hexlet-components/data-company-files.git
mv data-company-files/company-files company-files
rm -rf data-company-files
```

На Windows в наборе есть два файла, различающиеся только регистром имени
(`SCHETA-02-2025.CSV` и `scheta-02-2025.csv`), и один из них при клонировании пропадёт. Числа
тогда будут на единицу меньше, чем в примере ниже. Полный набор раскладывается в WSL, Linux,
macOS или в контейнере (см. «Проверка как у Хекслета»).

## Использование

```bash
file-automation                                   # справка
file-automation files ./company-files --out ./out
file-automation contacts ./company-files --out ./out
```

`--out` (`-o`) необязателен, по умолчанию результат уходит в `./out` текущей папки. В папку
компании программа ничего не пишет.

## Что получается на выходе

| Файл | Что в нём |
| --- | --- |
| `registry.csv` | строка на каждый файл папки: путь, имя, тип, размер, хеш, статус, основная копия, строк, колонки |
| `contacts.csv` | строка на человека: имя, телефон, почта, источники (через `; `) |
| `report.txt` | файлы под ручной разбор, файлы на удаление, группы дубликатов с лишним местом, сводка по выгрузкам контактов |
| `report.json` | те же данные структурой |

Отчёты одинаковые, какую бы команду ни запустили последней: каждая команда разбирает папку
целиком и берёт вторую половину чисел тем же кодом.

## Как программа решает

- **Тип.** Подпись формата в первых байтах (`%PDF`, `ÿØÿ`, `PK`, PNG, OLE) или нулевой байт
  делают файл непарсимым, как бы он ни назывался. Иначе решает расширение: csv и json —
  табличные документы, txt и md — текстовые. Файл без расширения без подписи и без нулевого
  байта считается текстовым.
- **Статус.** «Постороннее» — пустой файл, системный мусор (`.DS_Store`, `Thumbs.db`) или
  расширение вне списка csv, json, txt, md, pdf, jpg, jpeg, xlsx. «Требует ручного разбора» —
  документ, который программа не читает (pdf, сканы, xlsx). Остальное — «документ».
- **Дубликаты.** Файлы связаны, если совпал sha256 содержимого или имя после приведения
  (нижний регистр, без суффикса `(1)` и слова «копия», расширение сохраняется; подпапка не
  учитывается). Основная копия — файл ближе к корню, затем с уже приведённым именем, затем с
  коротким именем, затем по пути, поэтому ответ не зависит от порядка файловой системы.
- **Контакты.** Выгрузка — табличный документ, среди колонок которого есть телефон или почта
  по карте соответствий. Телефон приводится к 11 цифрам, начиная с `7`; почта — к нижнему
  регистру без пробелов, адрес без `@` отбраковывается; имя — без двойных пробелов, с заглавной
  буквы. Заглушки (`-`, `null`, `NULL`) становятся пустыми. Ключ склейки — телефон, а без
  него почта; запись без обоих отбраковывается.

Все расширения, подписи, колонки реестра, карта колонок контактов и заглушки собраны в
`src/config.js`: новый источник с новым названием колонки добавляется строкой в карту.

## Устройство

```text
bin/file-automation.js  разбор командной строки (commander) и печать
index.js                точка входа пакета: run({ command, directory, out })
src/config.js           все зашитые значения
src/walk.js             обход папки (рекурсивный, один на обе команды)
src/content.js          тип и статус по байтам и расширению
src/duplicates.js       хеш, приведение имени, группы копий
src/table.js            чтение csv/json (BOM, `;`, кавычки) и запись csv
src/files.js            разбор файлов и реестр
src/normalize.js        нормализация телефона, почты, имени
src/contacts.js         выгрузки, карта колонок, склейка, contacts.csv
src/report.js           report.txt (as-table для сводки) и report.json
src/commands.js         команды files и contacts
```

## Проверки

```bash
make lint   # ESLint
make test   # node --test: свои тесты на временной папке-хаосе
```

Тесты лежат в `test/*-test.js`. Суффикс `-test` выбран намеренно: автопроверка Хекслета
запускает vitest по всему репозиторию, и файлы `*.test.js` на `node:test` она бы приняла за
свои.

### Проверка как у Хекслета

Образ автопроверки открыт. Он кладёт репозиторий в `/project/code`, выполняет `make setup` и
гоняет свои тесты на скрытом наборе файлов:

```bash
docker pull mirror.gcr.io/hexletprojects/ai_engineer_file_automation_project_ru
docker run --rm -v "$(pwd):/project/code" \
  --entrypoint bash mirror.gcr.io/hexletprojects/ai_engineer_file_automation_project_ru \
  -c 'make setup && make test && make lint'
```

`make setup` в контейнере перезапишет `node_modules` под Linux; на Windows после этого
выполните `make setup` ещё раз (или смонтируйте копию репозитория без `node_modules`).
